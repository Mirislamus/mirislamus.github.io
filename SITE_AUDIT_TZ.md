# ТЗ по улучшению mirislamus.github.io

Дата аудита: 24 августа 2026 года  
Объект: `https://mirislamus.github.io/`, локальный репозиторий `mirislamus.github.io`  
Режим: точечное улучшение существующего сайта без редизайна

## 1. Цель

Повысить надёжность, доступность, убедительность контента, SEO и скорость сайта-портфолио, сохранив текущую визуальную систему, структуру карточек, темы, акцентные цвета и общий характер интерфейса.

## 2. Ограничения

- Не менять глобально визуальный стиль, композицию и набор секций.
- Не вводить новую дизайн-систему и новые страницы.
- Допустимы локальные UI-улучшения: контраст, состояния фокуса, поведение меню, семантика и аккуратная корректировка токенов светлой темы.
- Не добавлять в тексты непроверенные цифры, должности, результаты или клиентские утверждения.
- Сохранять EN, RU и UZ версии; каждое изменение интерфейсного текста синхронизировать во всех локалях.

## 3. Результат аудита

### 3.1. Оценка качества

| Направление | Оценка | Главное наблюдение |
| --- | --: | --- |
| Доступность | 2/4 | В светлой теме подтверждены 23 нарушения контраста; нет skip-link; меню не закрывается по `Esc` |
| Производительность | 3/4 | Загрузка быстрая, но первый экран передаёт около 196 КБ сжатого JS для одностраничного портфолио |
| Адаптивность | 3/4 | На 390 px горизонтального переполнения страницы не обнаружено |
| Темы | 2/4 | Три режима работают, но светлая тема не проходит WCAG AA; `color-scheme` не синхронизирован |
| Целостность реализации | 2/4 | Интерфейс цельный, но сборка и lint сейчас не проходят, есть битые ссылки |
| **Итого** | **12/20** | **Приемлемо, но необходим обязательный технический проход** |

По результатам аудита сформировано 8 укрупнённых задач: 5 обязательных и 3 задачи улучшения. Необязательные работы включены в соответствующие задачи и отдельно помечены как backlog.

### 3.2. Что уже сделано хорошо

- Цельная узнаваемая визуальная система без случайных компонентов.
- Корректные адаптивные сетки на desktop и mobile; на 390 px переполнения страницы не обнаружено.
- Тёмная, светлая и системная темы переключаются и сохраняются.
- Есть видимые `focus-visible`-состояния, семантические ссылки и кнопки в основных сценариях.
- Изображения проектов отдаются в WebP и загружаются лениво.
- Настроены локализованные URL, canonical, `hreflang`, Open Graph и sitemap-интеграция.
- Копирование email показывает доступное уведомление и имеет fallback.
- В единичном лабораторном прогоне опубликованной версии: FCP 288 мс, LCP 288 мс, CLS 0. Это положительный сигнал, но не замена Lighthouse и полевых данных.

## 4. Задачи реализации

### TASK-01. Восстановить проверки проекта

**Приоритет:** P1  
**Зависимости:** нет

Проблемы:

- `bun run build` падает при загрузке Astro config: `require is not defined` в `source-map-js/lib/source-map-generator.js`.
- `bun run lint` падает: отсутствует пакет `globals`; в `package.json` также не объявлены импортируемые `@eslint/js`, `typescript-eslint` и `eslint-plugin-react`.

Требования:

1. Устранить несовместимость Astro 7/Vite 8 при загрузке CommonJS-зависимостей.
2. Сначала проверить актуальное состояние зависимостей и upstream. Если ошибка воспроизводится на зафиксированных версиях, допустим документированный `createRequire(import.meta.url)` workaround для импортов Astro config с комментарием WHY/TODO.
3. Добавить все прямые зависимости ESLint config в `devDependencies`.
4. Добавить официальный type-check: `@astrojs/check` и script `check` на основе `astro check`.

Приёмка:

- `bun run lint` — exit code 0.
- `bun run check` — 0 errors, 0 warnings.
- `bun run build` — exit code 0, созданы EN/RU/UZ страницы и sitemap.
- После команд `git status --short` не показывает неожиданных изменений сгенерированных исходников.

### TASK-02. Исправить ссылки и настроить их проверку

**Приоритет:** P1  
**Зависимости:** TASK-01 — для запуска автоматической проверки

#### 2.1. Контактные ссылки

Файлы: `src/data/global.ts`, `src/widgets/components/Footer/Footer.tsx`.

Сейчас URL уже содержат `https://`, а Footer добавляет второй протокол. В опубликованной версии Telegram, GitHub и LinkedIn ведут на `https://https//…`.

Требования:

- Хранить в `info` полные canonical URL и использовать их без дополнительного `https://`.
- Отображаемую подпись Telegram получать отдельно от URL, не изменяя сам URL.
- Проверить обе Telegram-ссылки и ссылки GitHub/LinkedIn во всех локалях.

#### 2.2. Ссылки портфолио и навыков

Файлы: `src/data/projects/projects.json`, `src/data/career/career.json`, `src/data/skills/skills.json`.

- Ссылки JavaScript, HTML и CSS используют ошибочный домен `engineer.mozilla.org`. Заменить на `developer.mozilla.org`.
- Перед релизом автоматически проверить все внешние ссылки; допустимы 200–399, известные блокировки HEAD проверять обычным GET.

Приёмка:

- Контактные ссылки во всех локалях содержат один корректный `https://` и открывают ожидаемые адреса в новой вкладке.
- Ссылки навыков ведут на `developer.mozilla.org`.
- Автоматическая проверка внешних ссылок завершается без необработанных ошибок.

### TASK-03. Довести контраст светлой темы до WCAG AA

**Приоритет:** P1  
**Зависимости:** TASK-01

Файлы: `src/styles/helpers/_variables.scss` и компоненты, использующие `--accent`, `--grey-4`.

Подтверждено axe-core: 23 узла не проходят минимальный контраст. Затронуты hero, CTA, акцентные части заголовков, вторичный текст карточек, project cards, skills и reviews.

Требования:

- Не менять оранжевую стилистику глобально. Разделить декоративный accent и цвет акцентного текста, например `--accent` и `--accent-text`.
- Для светлой темы подобрать `--accent-text` с контрастом не ниже 4.5:1 на белом.
- На оранжевой fill-кнопке использовать тёмный текст либо более тёмный фон с контрастом не ниже 4.5:1.
- Ввести theme-aware `--text-muted`; текущий `#9a9a9a` не использовать как основной текст на белом.
- Проверить default, hover, active, focus и disabled состояния в обеих темах.

Приёмка: axe-core не находит `color-contrast` violations на `/`, `/ru/`, `/uz/` при light и dark; ручная проверка всех невычисляемых случаев завершена.

### TASK-04. Исправить accessibility и поведение интерфейса

**Приоритет:** P1  
**Зависимости:** TASK-01; проверка контраста выполняется в TASK-03

#### 4.1. Клавиатурная навигация и семантика

Файлы: `src/layouts/Layout.astro`, `src/widgets/components/Approach/Approach.tsx`, `src/widgets/components/Reviews/Reviews.tsx`, `src/widgets/components/Footer/Footer.tsx`.

Требования:

- Первым фокусируемым элементом добавить skip-link «Перейти к содержимому» / `Skip to content` / UZ-эквивалент; цель — `<main id="main-content">`.
- Убрать скачки `h2 → h4`: заголовки карточек Approach сделать `h3` либо обычным текстом, если это не самостоятельные подразделы.
- Имена авторов отзывов оформить через `<cite>`/`strong`, а не `h4`.
- Удалить запрещённый `aria-label` со `span` copyright; при необходимости использовать визуально скрытый текст.
- Декоративным изображениям/иконкам дать `alt=""` и `aria-hidden="true"`; содержательные alt локализовать.

#### 4.2. Мобильное меню и переключатель языка

Файлы: `src/widgets/components/Header/Header.tsx`, `Header.module.scss`.

Требования:

- `Esc` закрывает меню и список языков и возвращает фокус на кнопку-инициатор.
- При открытии меню закрывать список языков; при открытии списка языков закрывать меню. Сейчас список языков можно открыть за меню, но варианты перекрыты навигацией.
- Добавить `aria-controls`; синхронизировать `aria-expanded` и видимость.
- Для overlay использовать семантическую кнопку либо исключить его из accessibility tree и обеспечить полноценное закрытие с клавиатуры.
- Во время открытого мобильного меню исключить фон из tab-порядка (`inert`) либо реализовать корректное управление фокусом.
- Очищать `body.style.overflow` при размонтировании.

#### 4.3. `prefers-reduced-motion`

Файлы: `src/shared/ui/Avatar/Avatar.tsx`, `src/shared/ui/animations/RotatingText/RotatingText.tsx`, Footer.

Требования:

- Не запускать бесконечный GSAP morph аватара при `prefers-reduced-motion: reduce`; показывать статичную форму.
- Footer-текст не должен бесконечно меняться без возможности остановить. Предпочтительный вариант без нового UI: одна короткая entry-анимация и статичный финальный текст; при reduced motion — сразу статичный текст.
- Существующие reduced-motion правила view transitions сохранить.

#### 4.4. Локализация accessibility labels

Сейчас на RU/UZ остаются английские `Previous slide`, `Next slide`, `Go to slide N`, `Light theme`, `System theme`, `Dark theme`, `Language selector`, `Menu`.

- Передавать подписи в `ArrowControls`, Header и Swiper из locale data.
- Для пагинации использовать локализованное «Перейти к отзыву N».

#### 4.5. Синхронизация темы с браузером

- Установить CSS `color-scheme: light`/`dark` на `<html>` в зависимости от `data-theme`; сейчас computed value — `normal`.
- Обновлять корректный `meta[name="theme-color"]` при ручном выборе темы, а не только первый из двух media-зависимых meta.
- Проверить системную тему, ручное переключение и изменение OS theme без перезагрузки.

Приёмка:

- Первый `Tab` показывает skip-link и переносит фокус к `main`.
- Heading outline и ARIA-семантика логичны; axe-core не находит ARIA-нарушений.
- Меню и список языков корректно управляются мышью и клавиатурой, взаимно закрываются, возвращают фокус и не оставляют заблокированный scroll.
- При reduced motion нет циклического движения; информация не теряется.
- Accessibility labels локализованы в EN/RU/UZ.
- Режимы light, dark и system корректно синхронизируют `color-scheme` и `theme-color`.

### TASK-05. Снизить стартовый JavaScript и стабилизировать загрузку

**Приоритет:** P2  
**Зависимости:** TASK-01; поведение reduced motion из TASK-04 должно быть сохранено

#### 5.1. Предотвратить CLS у изображений

- Для project image задать реальные `width`/`height` либо стабильный `aspect-ratio`.
- Для skill icons задать размеры в разметке, не только в CSS.
- Сохранить WebP, lazy loading и JPG fallback.

#### 5.2. Снизить стартовый JavaScript

Текущий единичный замер первой загрузки: около 365 КБ transfer всего, из них около 196 КБ JS; крупнейшие JS chunks — примерно 80, 58 и 50 КБ. Для одностраничного портфолио это можно уменьшить без изменения UI.

Требования:

- Оставить React только для действительно интерактивных частей.
- Рассмотреть перенос статических Hero, текста Approach и Skills в Astro; theme-dependent изображения переключать CSS/picture без гидратации всего блока.
- GSAP/MorphSVG загружать только после проверки motion preference и только для hero.
- Swiper и Motion не должны попадать в первый экран до появления соответствующей секции.
- Не добавлять `will-change` постоянно.

Цель: стартовый сжатый JS ≤ 120 КБ без потери функций. Если bundle analysis покажет, что цель экономически нецелесообразна, зафиксировать фактический бюджет и причину.

#### 5.3. Backlog по шрифтам и ассетам

- Самостоятельно хостить тот же Inter и preload только реально используемых начертаний; визуально шрифт не менять.
- Удалить неиспользуемые SF Pro файлы либо документировать их назначение.
- Оптимизировать тяжёлый `zustand.svg`; originals JPG хранить отдельно от deploy artifact, если fallback сохранён.

Приёмка:

- Изображения имеют intrinsic size или стабильный `aspect-ratio`; CLS не появляется при загрузке проектов и навыков.
- WebP, lazy loading и JPG fallback сохранены.
- Стартовый JS не превышает 120 КБ gzip либо в отчёте зафиксированы измеренный бюджет и обоснование отклонения.
- Нет постоянного `will-change`; тяжёлые библиотеки не загружаются до момента использования.
- Backlog не блокирует основную приёмку TASK-05.
