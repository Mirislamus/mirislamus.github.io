# ADR 0024: Отступления сайта от шаблона ai-template

## Контекст

Шаблон ai-template внедрен в уже работающий сайт ([задача 001](../../tasks/001-ai-template-adoption.md)). Часть правил шаблона противоречит решениям, которые владелец принял раньше в волнах рефакторинга и доработок. По решению владельца при внедрении действуют решения сайта, а правила шаблона, которые им противоречат, не применяются.

Здесь перечислены только принятые отступления. Расхождения, по которым решения нет, ведутся как задачи в [docs/tasks.md](../../tasks.md).

## Решение

При расхождении ADR 0001–0018, [docs/design.md](../../design.md), [docs/tech.md](../../tech.md) или [docs/skills.md](../../skills.md) с этим документом действует этот документ.

### 1. Стек без React

- React удален целиком: Astro и TypeScript без UI-фреймворка, поведение — скрипты и custom elements.
- Не применяются: [ADR 0005](0005-react-standards.md), правила React-островов и гидратации ([ADR 0001](0001-project-architecture.md) §4), `lucide-react` (вместо него `@lucide/astro`), `clsx`, навык `$vercel-react-best-practices`.
- Карусели — `embla-carousel` без React-обертки (ADR 0010 одобряет пакет).

### 2. Нет форм, аналитики и бэкенда

- Не применяются: [ADR 0008](0008-forms-and-api.md), [ADR 0015](0015-analytics-and-tracking.md), [ADR 0006](0006-state-management.md) §2–3 (сторы), бэкенд-ADR 0019–0023, страницы политики и согласия ([docs/content.md](../../content.md)).
- ADR применяется, когда в продукте появится соответствующая функция.

### 3. Контент в JSON вместо Content Collections и словарей

- Тексты лежат в `src/data/<раздел>/*.json` с ключами локалей, данные без языка — в `*.base.json`; схемы и сборка — `src/data/schemas.ts`, `src/data/site.ts`.
- Не применяются: [ADR 0001](0001-project-architecture.md) §6 и словари TypeScript из [ADR 0016](0016-i18n-standards.md) §1–2. Цель ADR 0016 (сборка падает при пропущенном переводе) выполняется проверкой схем.

### 4. Собственные дизайн-токены и стилистика

- Токены сайта: `--gap-*`, `--text*`, `--primary`, `--accent*`, `--radius-*`, `--z-*` и др. в `src/styles/helpers/_variables.scss`. Шкала и имена из [docs/design.md](../../design.md) §1–5 не переносятся.
- Акцент `#ff6433` и цвета проектов не меняются; низкий контраст акцентного текста в светлой теме — принятое исключение, закодировано в `tests/e2e/a11y.spec.ts`.
- Стилистика Matrix и режим Relic (canvas-эффекты: дождь глифов, руки, маска, wordmark; синтезированный звук) приняты владельцем. Правило [docs/skills.md](../../skills.md) §2 о canvas и WebGL «ради выразительности» к ним не применяется; бюджет JS сайта строже шаблона (15 КБ gzip сразу, 10 КБ на чанк, `scripts/check-bundle.mjs`).
- Ripple-эффект кнопок сохраняется.
- Анти-шаблоны [docs/design.md](../../design.md) §9, п. 12 и 16, к сайту не применяются (решение владельца, задача 022): служебные строки через «·» (например, «Опыт более N лет · Ташкент»), почти черный фон с красно-оранжевым акцентом.
- Страница 404 — заставка Matrix без шапки и подвала ([паспорт 404](../../pages/404.md)).

### 5. Структура `src/` и адреса

- Структура `src/` остается своей, FSD-Lite из [ADR 0001](0001-project-architecture.md) §2 не применяется (решение владельца, задача 020): секции в `widgets/components/<Name>/`, папки компонентов в PascalCase, `styles/`, `utils/`, `data/`, `i18n/`, `seo/` на верхнем уровне `src/`. Описание — [ARCHITECTURE.md](../../../ARCHITECTURE.md). Именование папок kebab-case из [ADR 0004](../common/0004-ts-js-standards.md) §7 к папкам компонентов не применяется.
- Адреса страниц заканчиваются слэшем (`trailingSlash: 'always'`), вместо `'never'` из [ADR 0013](0013-seo-standards.md) §1 (решение владельца, задача 021): GitHub Pages отдает папки со слэшем, а адреса уже проиндексированы.

### 6. Хостинг GitHub Pages

- Сайт публикуется на GitHub Pages из `master`; ни один сценарий [ADR 0018](../common/0018-deployment-and-caching.md) §2 не подходит, заголовки `Cache-Control` и редиректы недоступны.
- Пуш в `master` деплоит сайт, поэтому работа идет в отдельной ветке, а пуш и мерж — только с разрешения владельца.
- Сайт пересобирается раз в месяц по расписанию, чтобы стаж и год обновлялись без коммитов.

### 7. Скриншотные тесты

- Сайт дополнительно к шаблону ведет visual regression (`tests/visual/`): эталон снимается только в GitHub Actions на `ubuntu-latest`, Docker не используется.

### 8. Исключения правил кода

- В тестах (`tests/` и `*.test.ts`) оператор `!` разрешен (решение владельца, задача 003): в тесте он означает «если элемента нет, тест должен упасть», и тест падает. В коде сайта запрет [ADR 0004](../common/0004-ts-js-standards.md) §10 действует.
- В тестах разрешен `any`: тесты читают произвольные поля JSON-LD без приведения на каждом узле.
- Пустой `catch` разрешен (`no-empty` с `allowEmptyCatch`) там, где браузерный API может бросить, а у сайта есть запасной путь: `localStorage` при заблокированных данных сайта, буфер обмена, аудио. Это отступление от [ADR 0004](../common/0004-ts-js-standards.md) §9.
- Единственное `as` в коде сайта — в типизированной утилите `fromKeys` (`src/utils/object.ts`), как `getKeys` в [ADR 0004](../common/0004-ts-js-standards.md) §1: `Object.fromEntries` не умеет вернуть `Record` с ключами-литералами.
- `tabindex="0"` разрешен на `role="group"`: прокручиваемые карусели и карточки должны получать фокус с клавиатуры.

### 9. Без комментариев в коде

- Комментарии в коде не пишутся (решение владельца): ни поясняющие, ни директивы линтеров. Правило «комментарий — только для неочевидной причины» из [AGENTS.md](../../../AGENTS.md) заменено этим. Причины решений записываются в сообщения коммитов, ADR и карточки задач.

## Последствия

- Агенты и субагенты сверяются с этим документом раньше, чем с ADR шаблона.
- Новое отступление добавляется сюда только после решения владельца.
