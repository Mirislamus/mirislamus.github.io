# Анимации и фичи mirislamus.github.io

Дата: 30 сентября 2026 Статус: согласовано с владельцем, к реализации после фазы 2 [`tz.md`](./tz.md) (сайт уже на Astro без React).

Этот документ описывает, **что меняется визуально и что добавляется**. Инженерные требования (архитектура, бюджеты, тесты, CI, a11y-база) задаёт `tz.md` и здесь не повторяются: каждая фича обязана им соответствовать.

---

## 1. Принципы движения

Выбран стиль **«один яркий момент + сдержанно»**:

1. **Один wow-момент** — Hero-интро (F-02). Всё остальное — тонкие микровзаимодействия в духе Linear и Vercel.
2. **Анимируются только `transform`, `opacity`, `clip-path`.** Никаких анимаций `width`, `height`, `top`, `margin`, `box-shadow` на каждом кадре.
3. **Не больше одной непрерывной анимации в кадре.** Сейчас это морфинг аватара; новые бесконечные анимации не добавляются (пульс статуса — конечный, F-08).
4. **Эффекты за курсором** (наклон, реакция аватара) работают только при `(hover: hover) and (pointer: fine)`.
5. **`prefers-reduced-motion: reduce`** отключает всё движение: элементы сразу в конечном состоянии, функциональность сохраняется.
6. **Без JS всё видно.** Стили начальных состояний анимаций включаются только при наличии соответствующего атрибута или `@supports`, контент никогда не остаётся скрытым.
7. **Без библиотек анимации.** CSS, Web Animations API, View Transitions, scroll-driven animations.
8. **Производительность:** 60 fps при 4× CPU throttling в DevTools; постоянный `will-change` запрещён.

### Бюджеты

| Что                                          | Бюджет                  |
| -------------------------------------------- | ----------------------- |
| JS, загружаемый сразу, после всех фич (gzip) | ≤ 15 КБ (как в `tz.md`) |
| Отложенный чанк палитры и терминала (gzip)   | ≤ 10 КБ                 |

### Волна 1. Фундамент и wow

#### F-00. Токены движения

- **Оценка:** 2 ч.
- **Что сделать:** в `_variables.scss` (поверх токенов из RF-16):
  - кривые: `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)` (появления, раскрытия), `--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1)` (перемещения), `--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1)` (только микроакценты: иконки, переключатели);
  - длительности: `--dur-fast: 150ms`, `--dur-base: 250ms`, `--dur-slow: 400ms`, `--dur-intro: 800ms`;
  - глобальный блок `@media (prefers-reduced-motion: reduce)`, обнуляющий длительности.
- **Приёмка:** все новые анимации используют только эти токены; stylelint запрещает «сырые» `cubic-bezier` и длительности вне `_variables.scss`.

#### F-01. Сдержанное появление при скролле

- **Оценка:** 2 ч.
- **Что сделать:** заголовки секций и группы карточек появляются один раз: `opacity 0 → 1`, `translateY(16px) → 0`, `--dur-slow`, `--ease-out`. Через `@supports (animation-timeline: view())` и `animation-range: entry 0% entry 40%`. В группах — задержка по индексу `--i × 40ms`, не больше 5 элементов. Абзацы текста не анимируются. Hero исключён (его ведёт F-02). Где нет поддержки — контент просто виден, JS-фолбэка нет.
- **Приёмка:** в Chrome/Edge секции появляются при скролле; в Safari/Firefox без поддержки всё видно сразу; CLS 0.

#### F-02. Hero-интро (wow-момент)

- **Оценка:** 6 ч.
- **Что сделать:**
  1. **Когда:** один раз за сессию вкладки. Блокирующий инлайн-скрипт в `<head>` (рядом со скриптом темы) проверяет `sessionStorage['intro-played']` и `prefers-reduced-motion`; если интро нужно, ставит `data-intro` на `<html>` до первой отрисовки. После окончания интро флаг записывается. Смена языка и перезагрузка в той же вкладке интро не показывают.
  2. **Хореография (≈1.1 с):**
     - 0–500 мс: аватар `scale(0.94) → 1`, `opacity 0 → 1`;
     - 150–650 мс: `h1` по словам — `translateY(100%) → 0` внутри маски (слова оборачиваются в `<span>` при сборке в Astro, без JS);
     - 450–750 мс: роль, затем текст — `opacity` + `translateY(8px)`;
     - 650–950 мс: кнопка;
     - 800–1100 мс: хедер съезжает сверху. `h1` не начинается с `opacity: 0` (только маска и сдвиг), чтобы не откладывать LCP.
  3. **Реакция аватара на курсор:** по `pointermove` в пределах Hero слой фото внутри маски смещается до 6 px, весь SVG поворачивается до 3°; сглаживание через `requestAnimationFrame` и lerp 0.12; плавный возврат при уходе курсора; обработчик выключается, когда Hero вне viewport.
  4. Все стили интро живут под `[data-intro]`: без JS и без атрибута страница выглядит как сейчас.
- **Приёмка:** интро один раз за сессию; при reduced motion и без JS его нет; LCP растёт не больше чем на 300 мс относительно версии без интро (замер Lighthouse mobile, медиана 5 прогонов); реакция на курсор отсутствует на тач-устройствах.

#### F-14. Смена темы «волной»

- **Оценка:** 3 ч.
- **Что сделать:** при клике по кнопке темы — `document.startViewTransition(() => applyTheme(next))`, затем Web Animations API анимирует `clip-path: circle(0 at x y) → circle(R at x y)` на `::view-transition-new(root)`, где `x, y` — центр нажатой кнопки, `R` — расстояние до дальнего угла экрана; `--dur-slow`, `--ease-in-out`.
  - На время перехода на `<html>` ставится класс, который снимает `view-transition-name` у хедера и `main` (иначе они анимируются отдельно от «волны» и не обрезаются кругом).
  - Существующие cross-document переходы при смене языка не затрагиваются.
  - Фолбэк: без View Transitions API, при reduced motion и при смене системной темы — мгновенно.
- **Приёмка:** волна идёт от нажатой кнопки на десктопе и в мобильном меню; повторный быстрый клик не ломает состояние; в Firefox без API тема меняется мгновенно.

### Волна 2. Header

#### F-03. Скользящая пилюля активного пункта

- **Оценка:** 2 ч.
- **Что сделать:** вместо полоски `.line` под пунктом — плашка за текстом активного пункта (`--accent-alpha`, радиус как у хедера). Позиция и ширина берутся из CSS-переменных, которые выставляет измерение RF-09. Анимируется только `transform` (принцип 2): сдвиг через `translateX`, ширина через `scaleX` с `transform-origin: left`; скругления рисуются псевдоэлементами по краям, которые не масштабируются. `--dur-base`, `--ease-in-out`. На мобильных остаётся текущее подчёркивание.
- **Приёмка:** плашка плавно перетекает при клике и при скролле; после ресайза и загрузки шрифта стоит точно под пунктом; при reduced motion переключается мгновенно.

#### F-04. Smart-hide хедера

- **Оценка:** 2 ч.
- **Что сделать:** при скролле вниз больше чем на 8 px после отметки 120 px хедер уезжает вверх (`translateY(calc(-100% - 20px))`), при скролле вверх возвращается. Хедер **не прячется**, если открыто меню или список языков, если фокус внутри хедера, во время открытой палитры или терминала. Слушатель пассивный, расчёт в `requestAnimationFrame`.
- **Приёмка:** хедер не «дрожит» при мелком скролле трекпадом; клавиатурный пользователь всегда видит хедер, когда фокус в нём; при reduced motion скрытие без анимации.

#### F-05. Шторка мобильного меню справа

- **Оценка:** 3 ч.
- **Что сделать:** мобильное меню (≤ 991 px) выезжает справа: ширина `min(360px, 85vw)`, на всю высоту, `translateX(100%) → 0`, `--dur-slow`, `--ease-out`; оверлей с `backdrop-filter: blur(8px)`. Внутри: пункты меню столбцом, переключатель темы внизу, кнопка закрытия. Focus trap, `Esc`, `inert` и scroll lock — из RF-09. Отступы с учётом `env(safe-area-inset-*)`.
- **Приёмка:** e2e-сценарий меню из `tz.md` проходит без изменений; на iOS Safari нет прокрутки фона под шторкой.

#### F-06. Строка прогресса чтения

- **Оценка:** 1 ч.
- **Что сделать:** линия 2 px по нижнему краю капсулы хедера (внутри скругления), `--accent`, `scaleX(0 → 1)` через `animation-timeline: scroll(root)`. Только под `@supports`, без JS. Скрыта при reduced motion.
- **Приёмка:** линия соответствует позиции скролла; в браузерах без поддержки её нет, и это не ломает хедер.

#### F-07. Кнопка «Наверх» с кольцом прогресса

- **Оценка:** 2 ч.
- **Что сделать:** круглая кнопка 48 px в правом нижнем углу (с учётом `safe-area-inset`), появляется, когда Hero ушёл из viewport (один `IntersectionObserver`). По контуру — SVG-кольцо, `stroke-dashoffset` от `animation-timeline: scroll(root)`; без поддержки — статичное кольцо. Клик: прокрутка наверх (`smooth`, при reduced motion — мгновенно) и перенос фокуса на ссылку-логотип. Локализованный `aria-label`. Не перекрывает уведомление (оно слева) и ripple.
- **Риск:** F-06 и F-07 оба показывают прогресс. На дизайн-ревью решить, оставить ли прогресс в обоих местах; запасной вариант — кольцо без прогресса.
- **Приёмка:** кнопка появляется после Hero и скрывается на нём; фокус после клика наверху страницы.
